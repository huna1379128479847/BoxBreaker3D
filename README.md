# LUMEN 
– 3D Block‑Breaking Game Specification

概要
	•	タイトル: LUMEN
	•	ジャンル: 3Dブロック崩しアクションパズル
	•	使用エンジン: Unity（Zenject, UniRx, UniTask を利用）
	•	視点: キューブを斜め上から見下ろす視点。球体がキューブの面上を移動する。
	•	舞台設定: 暗く抽象的なネオン世界。光だけが意味を持ち、他の物質は存在しない。

世界観：LUMEN
	•	この世界に存在するのは 光 (Lumen) とそれを遮る影 だけ。
	•	プレイヤーが操作する球体は 意志を持った観測点 (Active Lumen) であり、光そのものを象徴する。
	•	ゲーム空間は複数の キューブ から構成され、それぞれの面は異なる屈折条件を持つ光学面として機能する。球体は面から面へと連続して移動できる。
	•	ブロック は光を遮る遮光体、あるいはノイズ結晶。破壊は光路の解放を意味する。
	•	ダメージオブジェクト は不安定な屈折ノイズ。触れても進行は止めないが HP を減らす。
	•	壁 は光が跳ね返る境界。壁に衝突すると反射し、特定のリソース（ターン回数）が回復する。

ビジュアルスタイル
	•	ミニマルデザイン: テクスチャは極力シンプル。情報量を削ぎ、重要な要素だけを光らせる。
	•	ダーク背景: 背景はほぼ黒。世界の輪郭や床面は暗い色で、意味あるものだけがエミッション（発光）する。
	•	ネオンカラーパレット: 球体やブロック、UI はネオンカラーで輝く。色には意味を持たせる（例: 左ターンは緑、右ターンは赤）。
	•	UI: 白を基調とした文字に加え、操作を示す箇所は共通のカラーを割り当てる。文字自体の装飾は控えめで、読みやすさを重視。

基本ゲームメカニクス
	•	球体の移動
	•	球体は常に一定速度で各面を転がる。カメラはそれを追従し、斜め上から空間全体を捉える。
	•	面の縁に到達すると隣接する面に滑らかに移動し、ローカル座標系と向きを再計算する。
	•	反射とターン
	•	壁に衝突すると物理的な反射が起き、進行方向ベクトルが法線に基づいて変わる。
	•	壁衝突時に ターンチャージ（回転回数）が 1 回増える（上限あり）。
	•	プレイヤーは左右入力でターンチャージを消費し、固定角（例: 30°）だけ球体の進行方向を即時回転できる。
	•	入力を押している間は 時間がスローモーション になり、回転を狙いやすくする。キーを離した瞬間にターンが発動する。
	•	障害物とブロック
	•	ブロック: 破壊可能なオブジェクト。球体が接触すると壊れ、スコアを獲得する。複数の HP を持つブロックは HP が 0 になるまで打ち返す必要がある。
	•	ダメージオブジェクト: すり抜け可能だが球体の HP を減らす罠。接触時にダメージが発生し、破壊されることはない。
	•	壁: 移動を完全にブロックする固体。球体は反射して進行方向が変化し、ターンチャージが回復する。
	•	HP とスコア
	•	球体は HP（例: 3）があり、ダメージオブジェクトに触れると減少。HP が 0 になるとゲームオーバー。
	•	ブロックを破壊するとスコアが加算される。コンボや倍率システムを追加する余地がある。
	•	キューブ遷移
	•	サバイバルモードでは 1 つのキューブをすべてクリアすると、球体が中心に落下し、元のキューブが拡大しながらフェードアウト。次のキューブに着地してプレイが続く。難易度は徐々に上昇する（速度、ブロック配置数、危険物増加など）。
	•	操作
	•	左右キーのみ。ホールド時に時の流れが遅くなり、離した瞬間に進行方向を変更（ターン）する。非常にシンプルな入力で高速な状況判断を求める。

ゲームモード

キャンペーン
	•	あらかじめ設計されたステージを順番にクリアするモード。
	•	HP（残機）またはターン制限を共有しており、すべてのブロックを破壊すればステージクリア。
	•	ステージごとにスコアを記録し、クリア時に演出が行われる（時間減速 → ボール停止 → 球体が光の粒になって分解 → 通った軌跡がラインとして浮かび上がり → 消失 → 次のステージ／リザルトへ）。
	•	チュートリアルを兼ねた序盤ステージでは落ち着いた BGM とシンプルな配置で、基本操作や世界観をプレイヤーに伝える。

サバイバル
	•	体力が尽きるまで無限に続くキューブを連続でクリアしていくモード。
	•	キューブ内のブロックを全て破壊すると中央に落下し、元のキューブが拡大してフェードアウトしながら新しいキューブへ遷移。徐々にスピードやブロック密度が増し、難易度が上がる。
	•	スコアは無限に累積し、HP が 0 になるまで続く。ランキングやベストスコアへの対応が想定される。

オーディオ
	•	BGM: 各ステージにはステージテーマに合わせた BGM を用意。Sunо AI を用いて生成したインストゥルメンタルの電子音楽が基調。ミニマルで未来的な雰囲気とネオン世界の暗さを兼ね備え、ループが容易な構成とする。チュートリアルステージでは 90〜105 BPM 程度の落ち着いた曲調、後半のステージではテンポや強度を上げて緊張感を演出。
	•	効果音: 反射・ブロック破壊・ダメージ・ターン入力など、それぞれのイベントに合わせて光が弾けるような SE を使用する。UI の操作音も柔らかな電子音を採用し、全体の統一感を保つ。

アーキテクチャ (Model–View–ViewModel + Signals)

LUMEN は疎結合かつテスト容易な構造を志向し、Zenject と SignalBus による依存性注入とイベント駆動で Model ↔ ViewModel ↔ View を接続する。

Model (ゲームロジック)
	•	BallBehaviour: HP、速度、向き、ターン残量、ダメージ処理、リスポーン要求等を管理。Spawn/Despawn 演出の通知を所持。
	•	BallMover / RigidbodyMover: 球体の座標更新や反射計算を行う。Unity の Rigidbody を Kinematic として用いるか、自前の移動処理で制御。
	•	BallTurnService: プレイヤー入力を受け取り、球体の角度を変更するサービス。成功時に OnTurned シグナルを発行。
	•	BlockBehaviour: ブロックの HP 管理と破壊時のスコア付与、Surface への登録・破壊通知を担当。
	•	BallCollisionHandler: 壁・ブロック・ダメージオブジェクトとの衝突を検知し、反射やダメージ通知を行う。
	•	GameStateManager: プレイ中／一時停止／ゲームオーバー／クリアなどの状態管理と、状態遷移時の GameSignal 発行。
	•	GameDataHolder / ScoreHolder: スコアや残ブロック数などプレイ中のデータを保持し、外部から参照・更新できるようにする。

ViewModel (プレゼンテーションロジック)
	•	HPViewModel: HP の変更シグナルを購読し、UI に反映。ダメージ時に振動エフェクトをトリガーする。
	•	TurnViewModel: BallTurnService と BallBehaviour から情報を受け取り、左右ターンの予測ライン（LineRenderer）の角度計算や TurnView の更新を行う。
	•	ScoreLeaper: ScoreHolder の値をイージングを使って段階的に UI に反映させ、ゲームクリア時にアニメを開始する。
	•	BlockRemainingViewModel: 残りブロック数を滑らかに更新表示。
	•	その他: ゲーム開始・終了・再開などのシグナルを受け取り、各 View の表示状態を切り替える。

View (UI / 入力 / 演出)
	•	HPView: HP の数値やハート画像を表示。ダメージ時には小さく揺れるなどのアニメーションを追加予定。
	•	ScoreView / AbstractScoreView: スコアを描画し、ステージクリア時のエフェクトを DOTween 等で演出する。
	•	TurnView: LineRenderer で左右方向の予測線を描画し、ターン発生時に光の粒子エフェクトを再生。オブジェクトプールでパーティクルを管理。
	•	PaddleView: （パドルがないゲームでは不要だが）入力状態やターン残量の UI 管理に利用可能。
	•	GameOverView: ゲームオーバー時に表示される画面。リトライやメニューへ戻るボタンを提供する。
	•	TurnHandler: Unity の新 Input System を使用し、左右キーの押下を検知。ホールド中にタイムスケールを下げ、離したときに InputSignal を SignalBus へ投げる。
	•	Camera 機能: FollowBallCam や CamViewModel でカメラ追従やズーム／シェイク演出を制御する。ゲーム中のイベントごとにカメラを揺らしたり、拡大・縮小を行ったりして演出効果を高める。

演出
	•	反射エフェクト: 壁に当たるとカメラが微妙に揺れ、ターン残量が UI 上でポンと跳ねる。
	•	ダメージエフェクト: ダメージオブジェクトに触れると画面が赤くフラッシュし、時間が短くスローになる。
	•	ブロック破壊: 破壊時にエミッションが強く光り、小さな光粒子が飛び散る。連続破壊でコンボ感の演出が可能。
	•	ステージクリア演出: ボールが減速・停止し、光の粒に分解して消える。球体が通った軌跡が白〜シアンのラインとして浮かび上がり、徐々にフェードアウト。カメラはゆっくりと引き、次のステージや結果画面へ遷移する。
	•	サバイバル遷移演出: キューブ内のブロックを全て破壊すると時間が停止し、キューブの中央に落下。元のキューブが拡大・フェードアウトし、次のキューブに着地した瞬間に再びスピードが戻る。暗闇の中で光の粒が舞い、次のステージへシームレスに繋がる。

実装上の改善点と課題
	•	HPView の振動 (Shake) 実装: 振動エフェクトの具体的な動きは未実装。DOTween などで RectTransform の位置を揺らす実装が必要。
	•	TurnView エフェクトの正確な回転: 予測ラインの方向に合わせたパーティクルの回転調整が残っている。
	•	コンポーネント移行: BallBehaviour 等を Comp 系へ完全移行するタスクが継続中。ステートコンポーネントと処理コンポーネントを明確に分離し、参照依存を減らす。
	•	状態遷移管理: CanTransition / MarkTransition に関するルール付けがまだ不明瞭。ゲーム状態遷移中の入力無効化や演出管理を統一する必要がある。
	•	例外処理・null チェック: ViewModel 初期化時の null ガードや例外対策を強化し、非同期処理やオブジェクト破棄の安全性を高める。
	•	バランス調整: スピード、ターン角度、最大ターン数、HP などのパラメータチューニングやステージ設計が必要。プレイヤーが操作を覚えるためのリズムと適切な難易度設定が重要。
	•	サウンド実装: BGM 生成後のループポイント調整や効果音の具体的な選定、音量バランスの調整が未完了。

ゲーム進行の流れ（想定）
	1.	タイトル画面: LUMEN のロゴとシンプルなメニュー（キャンペーン／サバイバル）。
	2.	モード選択: 選択されたモードに応じてステージデータと BGM をロード。
	3.	ゲーム開始: ボールがスポーン。HUD（HP、ターン残量、スコア）が表示。BGM 再生開始。
	4.	プレイ中: プレイヤーが球体を操作してブロックを破壊し、障害物を回避。壁衝突でターンチャージを回復。ダメージオブジェクトに触れると HP を失う。
	5.	ステージクリア:
	•	キャンペーン: 全ブロック破壊で演出 → ステージ結果画面 → 次のステージへ。
	•	サバイバル: 全ブロック破壊で箱遷移演出 → 新しい箱に着地しプレイ続行。
	6.	ゲームオーバー: HP または残機が尽きるとゲームオーバー画面に遷移。リトライやタイトルへ戻る選択肢が表示。
	7.	リザルト／ランキング: スコア・経過時間・残機・コンボなどの結果を表示し、リプレイ性を高める。

⸻

この仕様書は、LUMEN のビジュアル／ゲームプレイ／システム構成／演出をまとめ、今後の実装・デザイン検討の基盤となることを目的としている。プレイヤーが 光の観測点 となって暗闇の立方体を走り回り、ネオンの軌跡を描きながら進む体験を提供するために、演出・世界観・UI・音を統一したミニマルな表現を徹底することがポイントである。
